# Linked memory, learning, selection and attention

29 September 2026 · Source review and implementation decisions

This intake connects the four supplied chats to the existing ARCHi runtime and iPhone app. It adds a research record and a concrete implementation sequence. It does not install WFM, train Qwen, enable Decisions API, or implement attention masks. Existing release blockers remain open.

## What each reference contributes

| Reference | Verified scope | Development use — our interpretation |
| --- | --- | --- |
| [WFM: Wiki Foundation Model for Complex Agentic Reasoning](https://arxiv.org/html/2609.18182v1), Dong et al., v1, 16 September | Couples passage text with typed graph structure and learned propagation. Section 4.4 describes unspecified entries as constructed planning values requiring measured validation. Its acceleration headline concerns distributed training. We retain performance claims as measurement-unresolved. | Extend ARCHi's existing linked, versioned pages with reviewed semantic relations and bounded retrieval paths. A Markdown wiki or new graph view alone does not reproduce the trained WFM. |
| [Recursive Self-Improvement via On-Policy Distillation for Reasoning](https://arxiv.org/html/2609.30652v1), Yin et al., v1, 25 September | DCE refreshes a privileged teacher; SRCL trains on filtered shorter rewrites. Qwen3-8B reaches reported Average@12 of 65.97 versus 30.35 for frozen OPSD and 62.08 for the base thinking mode. The 7.80% length reduction is relative to DCE, not OPSD. Small-model degradation limits generalization. | Capture independently checked, concise method examples and their exact provenance. Weight training requires a separate corpus, checkpoint identity, held-out evaluation and promotion/rollback path. Runtime Q2E adaptation remains distinct. |
| [OpenAI Decisions API announcement](https://openai.com/index/devday-2026-recap/), 29 September | Announces Luna-based selection from predefined answers using text/image context; limited preview at announcement. The reviewed announcement does not provide a request schema, pricing, calibration method or internal scoring equations. | A future optional selector may propose a route within the existing router. A selected answer cannot authorize external dispatch, an edit or durable memory. Use current typed contracts without inventing an API endpoint. |
| [Language Models Can Control Their Own Attention](https://arxiv.org/html/2609.02737v1), Ho et al., v1, 2 September | Declarative Attention uses a modified vLLM serving path to change KV block visibility. Reported attended-position reductions of 52.0% and 31.1% accompany accuracy losses of 1.27 and 2.75 percentage points. Decode-time estimates are projections, not measured application latency. | Improve explicit context selection now. Treat actual KV masking as a separately qualified backend change. Current Ollama and Apple model calls expose no such control. |

The equations and metric boundaries are in the [mathematical note](math-and-measurement.md). [Source register](sources.json) records primary versions and retrieval limits.

## What is already connected

These mechanisms have current source call sites; this review did not requalify their installed behavior.

- **Knowledge:** [ReadingSourceLibrary](../../../desktop/Sources/ARCHiDesktop/ReadingSourceLibrary.swift) owns retained sources and draft/reviewed/withdrawn page revisions. [KnowledgePage](../../../desktop/Sources/ARCHiDesktop/KnowledgePage.swift) already supports Claim and Concept pages with exact passage anchors. [KnowledgeRetrieval](../../../desktop/Sources/ARCHiDesktop/KnowledgeRetrieval.swift) already performs query-sensitive lexical ranking, freshness checks and bounded result selection. [KnowledgePageGraph](../../../desktop/Sources/ARCHiDesktop/KnowledgePageGraph.swift) derives navigation and attribution edges. This is the foundation to extend; a second wiki store is unnecessary.
- **Learning:** [KnowledgeProcedureIntegration](../../../desktop/Sources/ARCHiDesktop/KnowledgeProcedureIntegration.swift) connects reviewed concepts to explicit method candidates. [HamptonMethodOutcomes](../../../desktop/Sources/ARCHiDesktop/HamptonMethodOutcomes.swift) uses attributable application and subsequent review. [HamptonMethodResourceOutcomes](../../../desktop/Sources/ARCHiDesktop/HamptonMethodResourceOutcomes.swift) joins bounded resource observations. These mechanisms change method selection and runtime state; they do not train model weights.
- **Reasoning and routing:** [AssistantRouting](../../../desktop/Sources/ARCHiDesktop/AssistantRouting.swift), [LocalExpertPolicy](../../../desktop/Sources/ARCHiDesktop/LocalExpertPolicy.swift) and [HamptonProposalValidation](../../../desktop/Sources/ARCHiDesktop/HamptonProposalValidation.swift) already constrain destinations, local model choice and ANSWER/CLARIFY/ABSTAIN output. Existing Apply and outcome owners remain separate.
- **iPhone:** PhoneAssistantContext (`ios/ARCHi/PhoneAssistantContext.swift`, local workspace reference) supplies one explicitly selected phone note with its exact revision/digest. PhoneIntelligence (`ios/ARCHi/PhoneIntelligence.swift`, local workspace reference) creates a fresh Apple model session with no tools; ChatView (`ios/ARCHi/ChatView.swift`, local workspace reference) rejects cancelled or outdated completions. Mac pairing, shared live memory and cloud routing remain unconnected. See iPhone integration (`ios/INTELLIGENCE.md`, local workspace reference).

This supports Hampton's broader representation, reasoning, memory, adaptive computation and learning programme. Companion expression and Arena outcomes can consume attributable events through their existing owners; a new link, model answer or visual particle is not itself measured development. These references do not establish equivalence with Hampton's equations or demonstrate another vendor's use of his patent claims.

## Next implementation sequence

| Priority | Concrete change and existing owner | Completion evidence |
| --- | --- | --- |
| 1 | Add a small relation record to `ReadingSourceLibrary`: `supports`, `contradicts`, `dependsOn`, exact page-version endpoints, source anchors, declaration author and review state. Reuse existing revision/withdrawal rules and graph inspector. | A corrected/removed endpoint makes dependent context unavailable; restart preserves relation history; user-declared support never becomes automatic factual certification. Existing person relationships continue working. |
| 2 | Extend `KnowledgeRetrieval` with one-hop suggestions along current reviewed relations. Preserve lexical ranking as the baseline, show the relation path, keep current count/byte limits and require explicit inclusion. | Useful linked context appears without duplicate-source credit. Contradiction is visible rather than merged away. Cycles, stale endpoints and an exhausted budget cannot expand the request. |
| 3 | Extend existing method outcome/export records with exact prompt, settings, selected lessons, verifier version and workload identity. Produce an offline learning-candidate manifest. | Shorter examples retain relevant evidence and independently checked outcomes. Dataset splits and source-family deduplication prevent leakage. Export does not train, promote or replace a model. |
| 4 | Add only missing route/context receipt fields to current desktop and phone owners: policy version, allowed choices, selected destination, included revisions, omitted optional content, encoded size and effective limits. | A proposed route does not authorize transmission. A stale decision cannot execute. Limits and omissions are inspectable without persisting private prompt text. |

Priorities 1–2 are the next substantial memory upgrade. For the phone, first finish eligible-device Chat interaction acceptance and authenticated Mac pairing before transferring linked memory. Preserve the current bundle, companion identity, Field save and explicit transfer boundaries.

Full WFM training, DCE/SRCL weight updates and a Declarative Attention backend port belong in separately scoped implementation work. Their blockers are concrete: measured/reproducible WFM evidence, a qualified training/data/checkpoint toolchain, and an inference backend that actually exposes block-mask control. An available Qwen installation does not supply those mechanisms automatically.
