# Contributing through Hive

Hive coordinates proposals and moderator decisions for this public repository. Begin with [CONTRIBUTING.md](../CONTRIBUTING.md) for ownership boundaries, local checks, licensing and privacy. Hive membership and GitHub repository permissions are separate; neither grants the other.

1. **Join the project.** Use the project's approved Site access and open `/hive/projects`. Request membership and wait for moderator acceptance. Confirm the project's repository and target branch before preparing a change.
2. **Open a focused GitHub PR.** Work from the public repository on a branch or fork and target the configured branch. Complete the PR template with purpose, scope, test results and source/asset provenance. Keep private source, history, profiles and credentials out of the contribution. Regenerate `SOURCE_SHA256SUMS` after final edits and check complete coverage as required by the contributor rules.
3. **Submit it to Hive.** An active member supplies the existing PR URL, rationale and test evidence. Add the Hive project/proposal links to the PR without disclosing private project details. Hive reads GitHub metadata and diffs, records the exact head and base commits, and does not execute submitted code. If inspection fails, retain the draft and retry when the service permits; an old snapshot is not fresh verification.
4. **Obtain independent Hive review.** A different active moderator reviews the full PR and records approval, requested changes or decline with a reason. Hive's preview may omit binary or large patches. Approval applies only to the recorded head and base commits. After new source, a changed base, draft conversion or retargeting, refresh the GitHub data and obtain fresh review before merging.
5. **Complete GitHub review and merge.** An authorized maintainer must satisfy the repository's current branch protection and required independent GitHub review, then merge on GitHub. Hive approval is not a GitHub review or check run and cannot itself block a merge. GitHub review does not replace the Hive decision. Hive does not create or merge PRs automatically.
6. **Refresh GitHub in Hive.** Reconcile the actual PR state after the merge and inspect the result. A merge without matching prior Hive approval is flagged. If timestamp precision cannot establish the order of approval and merge, `merge_order_uncertain` remains unresolved; do not report it as a verified approved merge.

Include the tested commit, platform/toolchain, checks and observable results in each proposal. Mark checks passed, failed, skipped or not run, and explain gaps. A documentation-only change can report a focused documentation check; it does not demonstrate a hosted end-to-end workflow. Source merge, installed build and accepted user experience remain separate outcomes.

Project-authored contributions follow the repository's [MIT license](../LICENSE). Identify added material's origins and applicable terms, preserve [asset attribution](../ASSET_ATTRIBUTION.md) and [third-party notices](../THIRD_PARTY_NOTICES.md), and contribute only material you are authorized to share.
