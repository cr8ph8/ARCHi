# Security and private data

ARCHi is a development source candidate. This packet does not declare a supported production release, a security certification, a response-time commitment or a notarized application download. See [validation scope](docs/ALPHA_VALIDATION.md) for source, artwork and installed-app evidence limits.

## Report a vulnerability

Use [GitHub private vulnerability reporting](https://github.com/cr8ph8/ARCHi/security/advisories/new). Reporting was enabled and read back on 2 October 2026. If that option is unavailable to you, ask a maintainer for a private channel using only a nonsensitive summary; no dedicated disclosure address is published here. Do not post credentials, personal records or sensitive exploit details in a public issue.

A useful report identifies the affected source commit, platform/toolchain, boundary crossed, expected and observed behavior, and a minimal reproduction with synthetic data. Include the smallest relevant redacted log or test. Never attach an actual companion profile, conversation, document library, provider session, token or creator database. Do not test against another person's records or externally hosted services without their authorization.

## Current trust boundaries

- Native owners validate and retain identity, preferences, memory, source records and reviewed outcomes. Views, model responses, imported recipes and external panels do not independently authorize writes. See [native authority](docs/native-authority-and-lineage.md).
- Local and external model routes have separate admission and context rules. External-copy permission is scoped to the selected copy. A provider response or quoted instruction is data, not permission to act. See [model routing](docs/native-qwen.md).
- Unity receives a bounded presentation/session projection and can return checked observations. It has no authority to commit native growth or memories. Arena practice and acquired items confer no canonical rewards or effects.
- The creator service is restricted to loopback development use. Its accounts and publisher declarations do not establish verified identity or title. Production Internet hosting, payment processing, account recovery and operational service guarantees require separate work. See [creator service limits](marketplace/README.md#release-boundary).
- Native journals have no global cross-file transaction or cryptographic protection against a process able to rewrite the account's files. App rollback copies do not back up the live profile library. See [recovery boundaries](docs/one-app-system.md#application-backups).

## Source hygiene and verification

User profiles never belong in Git, including history and fixtures. Keep personal context, saved preferences/evolution, retained sources, conversations, provider artifacts, credentials, local databases and private backup inventories out of patches and publication candidates. Use disposable synthetic records for checks. Ignore rules and checksum manifests do not by themselves prove a source export is safe to publish.

Author fixes in the primary workspace and regenerate the curated publication from reviewed source; do not maintain a second writable profile or authored source in an export checkout. Review file coverage, private-data exclusions, notices and hashes before publication. Preserve unrelated authored work and live profiles while investigating a problem.

Run focused checks for the affected boundary and report what actually ran, including skipped tests and missing resources. A fixture pass is not live-provider acceptance, a security audit or installed-app qualification. Broad benchmarks are not a prerequisite for reporting or fixing a bounded issue. The [contribution guide](CONTRIBUTING.md) describes the available checks.
